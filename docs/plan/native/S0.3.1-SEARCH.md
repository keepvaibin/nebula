# S0.3.1: what is left at main of the shelved ray tracing (N-1053, N-1054)

The search of step S0.3.1, made at main 7b5ea882f before any change, for every name rows N-1053 and N-1054 give
and for the names the audit (`docs/audit-2026-11-17/B-findings-port.md`, section "RT: what to remove or switch off
to take it out of main") lists. S0.3.2 removes what this file lists, and keeps only what it names as kept, with the
reason.

How it was searched: `git grep -n -I -P "<pattern>" -- runtime native crates tools platform` (the card's five

source of `native/petari/src/Game/System/NebulaTextTable.inc` (`tools/nebula_text.py` builds it). A count is of
lines; a name in a comment or a test counts like one in code, and the last column says which it is.

## 3. What S0.3.2 has to read before it removes

- `tools/dev/build_programs.py` and `runtime/src/render/programs/table.tsv`: no line of any pattern above. The
  programs need no new build for the traced text, which went at store 36; S0.3.2 builds them again only if its change
  moves a program.
- `native/petari/src/Game/MapObj/ClipArea.cpp` includes `Game/Render/FrameList.hpp` (line 4) and uses no name the
  header declares in its own namespaces (`Frame`, `PassStates`, `LightValues`): the audit named this file for the
  clip volumes, which are gone; whether the include still serves another declaration is read in S0.3.2.
- The ray tables' check and the ray rows' check are live code that writes nothing (section 2). Their removal is S0.3.2's
  plan decision: a pack or a file that still carries them loads with them ignored.
