# The game's description of itself

## More rules

### Self-description

This is the shape, so G can plan luma-format, the validator and the LumaScript front end on it.

### What it is

One file that says everything a mod can name in one build of the game: functions, types, globals, game data in code,
and the game's data names (event flags, nerves, messages, tables). LumaLink, the LumaScript compiler and the editor
read it; nothing else is a source of names. Rule 4: it is generated by the build from the game's source (the same
pass that writes the function rows), never written by hand.

- Made at build time, beside the game module: `smg_game.luma-self.json` (and the same for the no-hooks module,
  which differs only in `module.hooks: false` and has no `functions[].invoke`).
- The same data is compiled into the module (the loader binds by it), and the game writes it on request
  (`--luma-describe <file>`). The build compares the two; a difference fails the build. So LumaLink can read either
  the file shipped with the game or ask the installed game, and get the same thing.
- Stable names. A name and signature, once in a released self-description, keeps its meaning. Upgrade test 9.15
  reads the first one against every later one.

### Shape (JSON, UTF-8)

```json
{
  "self": 1,
  "module": { "id": "<sha256 of the module>", "game": "RMG", "regions": ["RMGE01", "RMGP01", "RMGJ01"],
              "platform": "windows-x64", "abi": "msvc-x64", "luma_api": 1, "hooks": true,
              "built_from": "<commit>" },
  "functions": [
    { "name": "Kuribo::exeWander", "signature": "void()", "owner": "Kuribo", "kind": "method",
      "virtual": true, "const": false, "static": false,
      "returns": "void", "params": [], "hooks": ["before", "after", "wrap", "replace"],
      "file": "Game/Enemy/Kuribo.cpp", "line": 212 }
  ],
  "left_out": [ { "name": "...", "file": "...", "why": "template | header-only | allocation | ..." } ],
  "types": [
    { "name": "Kuribo", "kind": "class", "size": 412, "align": 4, "polymorphic": true,
      "bases": [ { "name": "LiveActor", "offset": 0, "virtual": false } ],
      "fields": [ { "name": "mVelocity", "type": "TVec3f", "offset": 36, "count": 1, "bits": null,

      "file": "Game/Enemy/Kuribo.hpp" },
    { "name": "MarioModule::State", "kind": "enum", "underlying": "s32",
      "values": [ { "name": "State_Wait", "value": 0 } ] },
    { "name": "f32", "kind": "alias", "of": "float" }
  ],
  "globals": [ { "name": "MR::sDefaultGravity", "type": "f32", "file": "..." } ],
  "data": [
    { "key": "Kuribo.cWalkSpeed", "type": "f32", "count": 1, "game": [2.0], "file": "Game/Enemy/Kuribo.cpp",

  "names": {
    "event_flags": ["SpinAndStarPointer", "..."],
    "event_values": ["LibraryOpenNewStarCount", "..."],
```

### Rules it keeps

- `functions[].name` + `signature` is exactly what `luma.h`'s `LUMA_FUNCTION` / `LUMA_HOOK_ON` binds; `types[].name`
  + `fields[].name` exactly what `LUMA_FIELD` binds. A name in one is a name in the other.
- Type text is as the game's source writes it after its own typedefs (`TVec3f`, `f32`), so a script reads the same
  words as the source.
- Every field of every class, struct and union the game defines, not only NameObj's; bit-fields with their
  bits; arrays with `count`.
- `left_out` lists every function without a row, with its reason; section 19 condition 1 is checked on it.
- Per platform: offsets and sizes may differ between ABIs, names never do. LumaLink reads one self-description for
  every platform it builds; a mod reaches a field of a game class through the offset the loader binds at load from
  the running game, not one taken from the file.

- Size: the Windows build's file is about 20 MB of plain JSON.
- Whether `tables` (BCSV columns) belong here or in the content census (they are game data files, not code).
- Nerve and message names: generated from the source like the rest (the old `tools/modding/*_list.py` listers'
  knowledge moves into the build's generator).

### As built, for G to read after it has run

Code: `tools/lumacore/self_description.py` (new), `native/CMakeLists.txt` (target luma_self_description),
`gen_types.py` (a virtual's `calls`; the header parse keeps bodies), `instrument.py` (a table's `keys`).

1. The file. `smg_game.luma-self.json`, beside the rows module, made by every build with rows (a cross build
   too: no run of the module is needed), compact UTF-8 JSON. The plain module has none: no mod's
   code runs on it. Measured on l22 (Windows x64): 21.0 MB, 1.24 MB with gzip -9. Shipped as is; compression is
   left to the packaging, which both sides already read (no new dependency).
2. Top level: `self` 1; `module` {id: sha256 of the module file, file, game "RMG", platform `<os>-<arch>`
   (windows, android, linux, macos, ios; x64, arm64), abi `msvc-<arch>` on Windows else `itanium-<arch>`, luma_api
   (luma.h's LUMA_API), hooks true, built_from: the source's git commit or null, said on stderr}; `functions` (the
   functions file's rows, C-6 marks included, unchanged); `types`, `globals`, `left_out` (the types file's,
   unchanged); `data` {numbers, tables} (the numbers file's); `names` {nerves, messages, keys}.
3. names.nerves: every class with the base Nerve: {name, owner, exe, file, line}. `exe` is the one function its
   `execute` calls, read from the body (types' new `virtuals[].calls`: every function a body the generator parses
   calls, by row name and signature, once each, in the order written); `owner` is that function's class. Null when
   execute calls none or several, or its body is not in the parse. Nothing is matched by name.
4. names.messages: every enumerator named ACTMES_* with its value.
5. names.keys: {table name: [string, ...]} for every array table whose rows all begin with a plain string
   literal (or are one), one per row, every row written (instrument.py `keys` on the table's row in the numbers file):
   the event flags (sGameEventFlagStatic), event values, the object factory's names and the rest. A row with no string,
   an escape, a macro's literal or fewer rows written than the array holds: no keys for that table.
6. Stops: a function (name) or a type (name, kind) given twice; luma.h without one LUMA_API; a missing
   input or module.
7. Compared: the types part is the module's own, as before (luma_types_check, compare_types.py). Functions and
   numbers are the generator's rows that the module is built from (the same pass); no second copy to compare.

G reads it from LumaLink (consumes). Limits: a nerve whose execute calls through a helper has a null exe; header
bodies parsed add to the generator's time (measured on l24, in RUNS).

### Places: as written

8. The file. `smg_game.luma-placement.json` beside the rows module, made by every build with rows (target
   luma_self_description, a cross build too) by `tools/lumacore/placement.py` from instrument.py's per-unit `.places`
   parts (the same parse that gives the rows: no second parse). Top level: `placement` 1, `factory`,
   `placement_args`, `left`.
9. factory: NameObjFactory.cpp's cCreateTable in its order: {name, class, creator}. A template creator
   (createNameObj< Kuribo >) gives its argument as the compiler resolved it; a function creator the one class its body
   news, its body in any unit (MR::createSuperSpinDriverPink, defined beside its class); null when it news none or
   several, or no unit defines it.
10. placement_args: {class: [row]} for every class with a read, its own or a base's. A row: {arg (0-7 for Obj_argN,
   null for a column read by its own name), field (the column: "Obj_arg0", "RotateSpeed"), type (s32, f32, bool: the
   overload), with_init, target (the field set, as written: "mObjArg0"; null for a local, an element or a helper's
   read), local (the local's or parameter's name), written (the argument's text), function, signature, file, line,
   from (the class whose method reads it), via ([] for a read in the method itself; else the functions the method
   hands its iterator to, the reading one last)}. Reads are MR::getPlacementArgN{NoInit,WithInit}(iter, &v) and
   MR::getPlacementArgNoInit(iter, "column", &v), recognised by the called function (the compiler's), never by
   text. A call from a method to another function taking a TableIter (a free function, another class's) gives that
   function's reads through `via`; the class's own and its bases' methods do not (their rows are there already).
   Sorted by arg, own before inherited.
11. left: free functions with reads that no method hands an iterator to ({function, file, reason}).
12. Stops: an instrumented unit without its .places part (naming it), two factory tables, no factory table, an
    owner or a factory class with no row in the types file, a function given by two units.

On real units (l22 commands, L24 sources): AreaObj::init 8 reads (mObjArg0-7), Kuribo 2 (a field, a local "state"),
the factory 1182 rows. The whole build's file: with build-l24-places (RUNS).
