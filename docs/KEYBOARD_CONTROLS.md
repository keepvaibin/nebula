# Controls

The game sees one Wii Remote with a Nunchuk on channel 0. Keyboard, mouse,
Xbox (XInput) controllers, Switch Pro Controllers and Switch 2 Pro
Controllers work at the same time; every Wii input can be rebound.

## Default maps

Controllers follow Super Mario Galaxy on Nintendo Switch (3D All-Stars; the
Switch 2 edition keeps the layout), with Star Bits on L/LB (Nintendo uses ZR),
ZR/RT as a spin button and ZL/LT as crouch.

| Action (Wii input) | Keyboard and mouse | Xbox | Switch Pro / Pro Controller 2 |
|---|---|---|---|
| Jump, confirm (A) | `Space`, `Enter`, left mouse button | A | A |
| Jump in play, back in menus | - | B | B |
| Star Bits, back (B) | `Left Shift`, `Right Shift`, right mouse button | LB | L |
| Crouch, ground pound (Z) | `Z`, `Left Ctrl`, `Right Ctrl` | LT | ZL |
| Camera reset (C) | `C` | Left stick click | Left stick click |
| Spin (Wii Remote shake) | `Q`, `E` | X, Y, RB, RT | X, Y, ZR, shake the controller |
| Move (Nunchuk stick) | `W` `A` `S` `D` | Left stick | Left stick |
| Camera, first person (D-pad) | Arrow keys | D-pad | D-pad; right stick while the gyro points |
| Pointer | Mouse, `I` `J` `K` `L` | Right stick | Gyro; right stick when the gyro is off |
| Pointer recenter | `R` | Right stick click | R |
| Pause (Plus) | `=`, `P` | Menu | Plus |
| Minus | `-`, `M` | View | Minus |
| Home | `H` | - | Home |
| 1, 2 | `1`, `2` (and numpad) | - | - |
| Shake (Nunchuk) | - | - | - |

B (controllers) never shoots Star Bits: it is Wii B (back) only while a
screen with a Back action is open, Wii A (jump) otherwise. The runtime reads
the game's pointer mode (`StarPointerOnOffController::mMode`): HOME menu,
error window, pause menu and galaxy map, logo, title, file select, star
select, yes/no prompts, picture book and the dome galaxy selector are menus;
every other mode, and a mode it cannot read, is play. The choice is made when
B goes down and kept until it is released. L/LB always send Wii B. Switch
buttons are by label (Nintendo A is Wii A); Xbox buttons by position.
Capture, GL, GR and C (Pro Controller 2) are unbound by default.

Pointer recenter: press R (Switch), the right stick click (Xbox) or `R`
(keyboard) to put the pointer in the middle of the picture; it also brings a
hidden pointer back, on any menu. While the button is held the pointer stays
in the middle and gyro or stick motion is ignored; on release it moves from
the middle, so the controller's direction at release is the new centre.

Still pointer: a controller pointer that stays within
`tune.<scheme>.pointer_hide_radius` (default 0.12, 6% of the picture width,
2.4 degrees of turn) of where it settled for `pointer_hide_seconds` (default
2; 0 never hides) disappears, as in the Switch ports. Hand tremor and small
jerks inside the radius do not restart the timer; the position is smoothed
over 0.1 s, so a single-report spike does not count. Moving out of the radius,
the recenter button or (stick pointer) a stick push brings it back. The mouse
never hides this way.
Sources for the Switch behaviour (player reports; no official timing exists):
[ResetEra, Galaxy + Galaxy 2 (Switch 2) review thread](https://www.resetera.com/threads/super-mario-galaxy-super-mario-galaxy-2-review-thread.1312336/page-16)
("if you're not actively using it for a bit it kind of just disappears on its
own", "you have to recenter with R a lot"),
[GameFAQs, 3D All-Stars: removing the pointer](https://gamefaqs.gamespot.com/boards/299724-super-mario-3d-all-stars/79019437)
(press R to recenter, the pointer goes invisible when unused),
[GameFAQs, 3D All-Stars: pointer issues](https://gamefaqs.gamespot.com/boards/299724-super-mario-3d-all-stars/79020720)
(R returns a runaway pointer to the centre).

Camera on the right stick: the game turns the camera one step per D-pad
left/right press (`CameraLocalUtil::testCameraPadTriggerRoundLeft/Right`
test the press edge), so one push of the stick is one step, as one press of
the Wii D-pad.

## Input sources

`input_mode=auto` (default): all sources are live. The pointer belongs to
whichever source moved last (mouse, pointer keys, right stick, gyro); another
source takes it over after the current one has been still for 250 ms. A
connected controller keeps the pointer on screen. With a controller attached,
key and mouse input generated by SendInput (Steam's desktop controller
layout, which turns the same buttons into keys and the right stick into mouse
motion) is ignored. `keyboard_mouse` and `controller` keep only that source.
`GALAXY_INPUT_MODE` overrides the file.

- Mouse: the position points while the cursor is inside the game picture,
  also when another window has focus; keys and mouse buttons need the game
  window focused.
- Right stick: radial dead zone, slow near the centre and `pointer_speed` at
  full deflection, integrated with the real time between input reports;
  the pointer stops at the picture edge.
- Gyro (Switch): turning the controller about the vertical moves the
  pointer sideways, tilting it moves it up and down, held flat or upright.
  One picture width is 40 degrees at `gyro_sensitivity=1`. Gyro bias is
  re-measured whenever the controller rests. Pointed past the picture the
  pointer disappears, as with a Wii Remote, and returns when turned back.
- Shake (Switch): a jolt of the controller (acceleration with gravity
  removed) or a fast wrist flick; held 60 ms, at most one per 280 ms.
- Tilt (Star Ball, ray surfing): the game steers these with the Wii Remote's
  accelerometer only. Pro Controller and Pro Controller 2: the hold when the
  section starts is level (R takes the current hold as level again); tilt
  left, right, forward or back to roll the ball, tilt left or right to steer
  the ray. Xbox controllers steer with the left stick, the keyboard with `W`
  `A` `S` `D`. The controller used last decides. Outside these sections the
  remote's accelerometer stays at rest, and the pointer never rotates with
  the controller.
- Vibration: when the game runs the Wii Remote's motor (a Star Bit shot,
  a hit, an earthquake), the controller in use vibrates for exactly as long:
  Xbox controllers through XInput, Pro Controllers with HD rumble, Pro
  Controller 2 (USB) with its rumble report. A key or mouse button bound to a
  Wii input hands vibration to the keyboard (none). The motor stops at once
  when the game window loses focus, a pause, HOME or settings menu opens, the
  game stalls for 100 ms, the controller disconnects, or Nebula exits or
  crashes. `tune.<controller>.rumble` sets the strength (`0` off, `25`, `50`,
  `75`, `100`). A real Wii Remote receives the game's own motor commands.

## Remapping

In game: `F1`, View+Menu (Xbox) or Minus+Plus (Switch), page CONTROLS.

| Row | Keyboard | Controller |
|---|---|---|
| INPUT: auto, keyboard+mouse only, controller only | Left/Right | D-pad/stick |
| EDIT: scheme shown below | Left/Right | D-pad/stick |
| Binding row: add the next pressed input | `Enter` or Right | A |
| Binding row: clear | `Backspace` | X |
| Cancel waiting for an input | `Esc` | - |
| Apply the page | `Space` | Y |

Each Wii input holds up to four inputs; adding a fifth replaces the last.
Stick and pointer directions accept stick directions and buttons; the mouse
buttons bind only to button rows. A stick direction bound to a button row
presses at half deflection and releases below 35%. A right-stick direction
bound both to a pointer row and to another row is the pointer while the gyro
is off and the other row while it points. Controller-only input is selected
only while a controller is attached. Nebula settings (NebulaSettings.exe,
first launch) has the same choices on its Controls tab.

Settings are stored in `runtime_settings.ini` next to `config.ini`:

```
input_mode=auto
controls_version=4
bind.keyboard.a=Space, Enter, MouseLeft
bind.xbox.jump_back=B
bind.switch_pro.b=L
tune.switch_pro.gyro_sensitivity=1
```

Schemes: `keyboard`, `xbox`, `switch_pro`, `switch_pro2`. Targets: `a b one
two plus minus home dpad_up dpad_down dpad_left dpad_right stick_up
stick_down stick_left stick_right c z shake nunchuk_shake pointer_up
pointer_down pointer_left pointer_right pointer_recenter jump_back`. Input
names: key names (`Space`, `LShift`, `W`, `Num1`, `F5`, `Equals`, `VK2E`),
`MouseLeft` `MouseRight` `MouseMiddle` `Mouse4` `Mouse5`; Xbox `A B X Y LB RB
LT RT LS RS Menu View DpadUp...`; Switch `A B X Y L R ZL ZR LS RS Plus Minus
Home Capture GL GR C DpadUp...`; sticks `LX+ LX- LY+ LY- RX+ RX- RY+ RY-`.

Files with an older `controls_version` are migrated on load: bindings that
still hold the defaults of Native28 (no version), Native29 (version 2) or
Native29b (version 3) take the version-4 defaults; a Native28 file's gyro
switch and `input_mode=keyboard_mouse` take `1` and `auto`; a version-3
still-pointer time of 4 s and radius of 0.03 take 2 s and 0.12; anything else
the player changed stays.

| Tuning (`tune.<scheme>.`) | Values | Default |
|---|---|---|
| `pointer_speed` | 0.2-6.0 (pointer units per second at full deflection; 2 = picture width) | keyboard 1.6, controllers 2.4 |
| `invert_pointer_y` | 0/1 | 0 |
| `stick_deadzone`, `pointer_deadzone` | 0-0.5 of full deflection (pointer: radial) | Xbox: XInput defaults (0.24, 0.27); Switch 0.12 |
| `motion` (Switch) | `off`, `remote`, `nunchuk` | `remote` |
| `shake_sensitivity` (Switch) | 1 (hard shake) - 5 (light) | 3 |
| `gyro_pointer` (Switch) | 0/1 | 1 |
| `gyro_sensitivity` (Switch) | 0.2-5.0 (1: a picture width per 40 degrees) | 1 |
| `pointer_hide_seconds` (controllers) | 0-60 seconds within the radius before the pointer hides; 0 never | 2 |
| `pointer_hide_radius` (controllers) | 0-0.5 pointer units (2 = picture width) | 0.12 |
| `rumble` (controllers) | 0, 25, 50, 75, 100 percent vibration strength; 0 off | 100 |

`GALAXY_XINPUT_LEFT_DEADZONE`, `GALAXY_XINPUT_POINTER_DEADZONE`,
`GALAXY_XINPUT_POINTER_SPEED`, `GALAXY_KEYBOARD_POINTER_SPEED` and
`GALAXY_XINPUT_TRIGGER_THRESHOLD` (default 96 of 255) override these.

## Controllers

- Xbox: every XInput slot (0-3) is read. `GALAXY_DISABLE_XINPUT=1` disables
  it, `GALAXY_XINPUT_REQUIRE_FOCUS=1` reads it only while the window has
  focus.
- Switch Pro Controller: USB or Bluetooth (HID). Nebula reads the stick and
  IMU calibration from the controller, switches it to full reports with the
  IMU on, rumble off and player LED 1.
- Switch 2 Pro Controller: USB only. It sends input only after a vendor
  command on its second USB interface, which needs the WinUSB driver (for
  example installed for "Interface 1" with Zadig); without it the CONTROLS
  page shows NEEDS WINUSB. Over Bluetooth it is a Bluetooth LE device that
  Windows does not expose as HID; not supported.
- Steam: with Steam's controller support on, Steam keeps its desktop layout
  on Nebula's window (Nebula is not a Steam game). Auto mode ignores the
  keys and mouse motion that layout generates while a controller is
  attached; the overrides do not.

Switch protocol details follow SDL's zlib-licensed `SDL_hidapi_switch.c` /
`SDL_hidapi_switch2.c` and dekuNukem's Nintendo_Switch_Reverse_Engineering.
The gyro pointer's world-space axes follow JoyShockMapper's description of
player/world space. Switch layout: Outsider Gaming "Super Mario Galaxy Switch
controls", GamerGuides "Super Mario 3D All-Stars controls", MarioWiki "Super
Mario Galaxy 2" (Switch controls); Star Bits moved from ZR to L by player
choice.

Star Bits and the drawn pointer use the same sample: for every host pointer
source the runtime answers the game's pointer depth query
(`StarPointerController::storeDataFromCallback`) from the scene depth it
captures at `StarPointerPeekZ`'s scene token, not from the end-of-frame EFB.
Every store of an active pointer is answered at the current position: when
this scene's field cannot be used, the newest completed field (or the last
answered depth) gives the depth. The game aims Star Bits at the stored world
point when it is within 3000 units of Mario, so a store left unanswered would
send them to an older pointer position.

## Native Settings Overlay

`F1`, View+Menu (Xbox) or Minus+Plus (Switch) opens or closes the settings
overlay; a one-line hint names them for the first seconds of a session, and
the file-select screen shows a PC SETTINGS button. Autorepeat never toggles
it. While it is open the game sees no keyboard or controller input, and
buttons held when it closes stay hidden from the game until released.

| Keyboard | Controller | Settings action |
|---|---|---|
| `F1` | View+Menu, Minus+Plus | Open or close |
| `Tab` / Page Down, Page Up | RB/R, LB/L | Next, previous page |
| Up / Down | D-pad or left stick up/down | Select row |
| Left / Right | D-pad or left stick left/right, A | Change the selected row |
| `Enter` | Y | Apply (CONTROLS: `Space`/Y) |
| `Backspace` | X | Undo the draft (CONTROLS binding row: clear) |
| `Esc` | B or Menu/Plus | Close; an unapplied draft is discarded |

On Switch controllers the overlay uses the console's meaning: A changes, B
closes. Pages: DISPLAY, GRAPHICS, CONTROLS, AUDIO (changes apply live), CAPS
(read-only). Settings files are written through flushed sibling temporaries
and atomically replaced; a failed save stays dirty and is retried on the next
close or at shutdown.

## Headless Diagnostics

Automated runtime probes can script input by VI retrace:

| Env var | Format |
|---|---|
| `GALAXY_INPUT_AUTOPRESS_SCRIPT` | `start:duration:buttons;...`, e.g. `5400:120:A+B` |
| `GALAXY_INPUT_AUTOPRESS_SCRIPT_STOP_AT_MARIO_CONTROL` | `1` to stop the long-form button script at the first translated Mario-control boundary; successful diagnostic runs emit one `[input-script-stop]` record and hard-fail if that source contributes A/B afterward |
| `GALAXY_INPUT_AUTOPRESS_SCRIPT_STOP_FALLBACK_VI` | Absolute HID-timeline VI used only before a live Mario-control marker is published; the live marker is authoritative afterward |
| `GALAXY_INPUT_STICK_SCRIPT` | `start:duration:x:y;...`, with stick axes clamped to `-1..1` |
| `GALAXY_INPUT_STICK_SCRIPT_RELATIVE_MARIO_CONTROL` | `1` to treat stick script times as relative to first Mario-control VI |
| `GALAXY_INPUT_STICK_SCRIPT_RELATIVE_FALLBACK_VI` | Absolute VI fallback anchor for relative stick scripts when the Mario-control marker is absent |
| `GALAXY_INPUT_SHAKE_SCRIPT` | `start:duration;...`, stages report-level Wii Remote shake acceleration |
| `GALAXY_INPUT_POINTER_X`, `GALAXY_INPUT_POINTER_Y` | Pointer coordinates clamped to `-1..1`, active for the whole run |
| `GALAXY_INPUT_POINTER2_X`..`GALAXY_INPUT_POINTER6_Y` plus matching `*_VI` | Pointer waypoints that become active at the given VI |
| `GALAXY_INPUT_POINTER_SWEEP_VI`, `GALAXY_INPUT_POINTER_SWEEP_DURATION` | Horizontal pointer sweep over a VI window |
| `GALAXY_INPUT_REPLAY_LOG` | Path to a `tools/measure_inputs.ps1` TSV; replayed as virtual host input before HID report formatting |
| `GALAXY_RUMBLE_TRACE` | `1` logs the game's Wii Remote motor transitions (`[rumble]`) and what the controller in use would receive (`[rumble-out]`); no controller vibrates in such a session or with `GALAXY_HIDE_WINDOW` |
| `GALAXY_TEST_RUMBLE_TARGET` | `xinput:N` or `switch:N`: the controller `[rumble-out]` reports for, with the window counted as focused (trace sessions only) |
| `GALAXY_TRACE_TILT` | `1` logs tilt sections and the accelerometer reading sent (`[tilt]`) |
| `GALAXY_TRACE_NATIVE_MOUSE_POINTER` | `1` logs pointer depth stores (`[mouse-pointer-frame]`) and world points (`[pointer-world]`); `_ROWS`, `_FROM_VI` limit them |

These hooks are for deterministic native-runtime diagnostics and do not affect
normal interactive input unless the environment variables are set. Treat them as
proof inputs only when `[input-trace]` shows the expected nonzero report-level
button, stick, pointer, or shake samples on the native Bluetooth/HID boundary.

`tools/run_release_diagnostics.ps1 -TraceInput -InputMode controller` records
`[input-trace]` lines with `source=`, `ptrsrc=`, controller slot, stick values,
pointer coordinates, `shake=`, and the native input boundary (`boundary=bt-hid`
for the virtual Wii Remote path or `boundary=bt-hid-real` for real-device
pass-through).
The diagnostics analyzer treats traced input as proven only when those native
boundary tokens are present and well-formed.
The diagnostics runner always launches the visible Release runtime and clears
`GALAXY_HIDE_WINDOW`.

## Audio Diagnostics

The native DSP mixer exposes persisted gain controls used by the native
settings UI and release launcher:

| Env var | Lane |
|---|---|
| `GALAXY_AUDIO_MUSIC_GAIN` | JAudio sequence/stream music |
| `GALAXY_AUDIO_EFFECTS_GAIN` | shared non-music effects bus |
| `GALAXY_AUDIO_SFX_GAIN` | sound-effect owner categories |
| `GALAXY_AUDIO_VOICE_GAIN` | voice owner categories |
| `GALAXY_AUDIO_AMBIENCE_GAIN` | atmosphere/ambience owner categories |

Each value is a scalar from `0.0` to `4.0`; unset means `1.0`.

Audio stem tracing can be narrowed for live voice/SFX probes:

| Env var | Format |
|---|---|
| `GALAXY_TRACE_AUDIO_STEMS` | set to `1` to log JAudio owner lanes |
| `GALAXY_TRACE_AUDIO_STEMS_START_SYNC` | first DSP sync frame to trace |
| `GALAXY_TRACE_AUDIO_STEMS_END_SYNC` | last DSP sync frame to trace |
| `GALAXY_TRACE_AUDIO_STEMS_LANE` | comma-separated `music`, `sfx`, `voice`, `ambience`, `unknown`, or `all` |
